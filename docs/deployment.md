# 部署与维护

## 单机部署

1. 在自己的服务器安装 Node.js 24 和 Python 3.12，安装依赖并构建网页。
2. 配置独立 `.env`，使用自己的随机管理员密码和 HTTPS `PA_PUBLIC_ORIGIN`，设置 `PA_SECURE_COOKIE=true`。
3. 将存储和数据库放在有备份的持久目录中；单独保护 `.env` 的读取权限。
4. 使用进程管理器分别运行 API 与 worker。两者读取相同环境变量、数据库和数据目录，仅部署一个写入站点。
5. 在 TLS 反向代理后运行 Uvicorn，例如：

```sh
PYTHONPATH=backend .venv/bin/python -m uvicorn app.main:create_app --factory --env-file .env --host 127.0.0.1 --port 18770
.venv/bin/python scripts/run.py worker
```

所有命令均从仓库根目录执行；进程管理器应设置相同工作目录。

通用 Nginx 示例见 `deploy/nginx.conf.example`。填写自己的域名及证书路径。静态页面和 API 都转发到同一个服务，不要直接暴露 `data/`、数据库、原始文件或分块目录。

示例是起点，未包含证书签发、云防火墙、服务自动重启或容量配置。首次部署先用未发布内容验证权限和上传处理，再公开作品。

## 升级

备份数据库、数据目录和私有配置，再更新源码、安装依赖、重新构建网页。维护窗口停止 worker 和 API，更新后启动 API（自动迁移）与 worker。迁移失败时先恢复匹配的数据库和源码，不在生产库上盲目重试。

此仓库使用独立初始 schema，**不能直接用于接管既有私人版本数据库**。数据迁移需单独编写并验证。

## 备份

最简单的一致备份：暂停 API 和 worker 后复制完整数据目录与数据库，再恢复服务。SQLite WAL 模式下不要在写入期间只复制单个 `.sqlite3` 文件；在线备份请使用 SQLite backup API，并与媒体文件建立一致快照。

备份、原图和 `.env` 应在仓库之外保存，定期验证能在隔离目录恢复。回收站不等同备份。

## 小程序更新

后端先上线兼容接口，再分别更新网页和小程序。小程序有审核和客户端更新周期；公开接口变更应保留旧字段和旧路径，或者提供并行的新版本。源码 tag 可以共同标记一次产品版本，实际网页部署与微信发布状态分别记录。
